# 端到端（E2E）测试体系

## Motivation

当前 QuantFlow 的测试覆盖：

| 层级 | 覆盖 | 不足 |
|------|------|------|
| 单元测试 | ✅ Go 213 文件 / 前端 68 文件 | 无法验证跨层级交互 |
| 集成测试 | ⚠️ Go 包内集成测试 | 无法验证 Wails IPC + WebSocket 全链路 |
| E2E 测试 | ❌ 不存在 | 无任何端到端验证 |

财务类应用的关键路径（行情展示 → 下单 → 回测 → 工作流）完全依赖手动测试。每次重构（如 WS 迁移）只能靠单元测试保证局部正确性，无法验证用户视角的完整功能。

### 跨层级 Bug 案例

```
前端 setInterval → Wails IPC → Go FetchQuote → REST API
       ↓
WS 迁移后:
前端 WebSocket → wsHub → QuotePoller → Go FetchQuote → REST API
```

单元测试分别覆盖前端 WS 处理和 Go 轮询逻辑，但无法捕获"前端 WS 连接失败时无任何数据展示"这类全链路 bug。

## Design

### 1. 技术选型

**Playwright** (Microsoft) + **Wails dev mode**。

| 选项 | 选择理由 |
|------|---------|
| Playwright 而非 Cypress | 跨浏览器支持、网络拦截、更快的 CI 集成 |
| Wails dev mode | `wails dev` 启动完整应用（Go 后端 + Vite 前端），Playwright 连接 `localhost:34115` |
| 非 Electron | Wails 是原生窗口，E2E 测试需要启动真实 Wails 进程而非 mock |

### 2. 架构

```
Tests (Playwright Node.js)
  │
  ├── wails dev 启动应用 (Go backend + Vite HMR)
  │     └── 等待 http://localhost:PORT 可用
  │
  ├── 测试用例
  │     ├── 导航 → 确认面板标题
  │     ├── 搜索股票 → 确认行情显示
  │     ├── WebSocket 连接 → 确认实时数据到达
  │     ├── 工作流创建/执行 → 确认结果
  │     └── 崩溃恢复 → 确认自动重连
  │
  └── wails dev 进程终止
```

### 4. Wails 启动/关闭 helper

```typescript
// frontend/e2e/helpers/wails-launcher.ts
import { ChildProcess, spawn } from 'child_process'
import path from 'path'

export class WailsApp {
  private process: ChildProcess | null = null
  private port: number = 0

  async start(): Promise<string> {
    return new Promise((resolve, reject) => {
      const projectRoot = path.resolve(__dirname, '..', '..', '..')
      
      this.process = spawn('wails', ['dev', '-nocolor'], {
        cwd: projectRoot,
        env: { ...process.env, WAILS_HEADLESS: '1' },
      })

      // 从 stdout 解析端口
      this.process.stdout?.on('data', (data: string) => {
        const match = data.match(/http:\/\/localhost:(\d+)/)
        if (match) {
          this.port = parseInt(match[1])
          resolve(`http://localhost:${this.port}`)
        }
      })

      // 超时处理
      setTimeout(() => reject(new Error('Wails dev timeout')), 30000)
    })
  }

  async stop() {
    if (this.process) {
      this.process.kill('SIGTERM')
      this.process = null
    }
  }
}
```

#### 5c. WebSocket 连接/重连

```typescript
// websocket.spec.ts
test('WS 断开后应自动重连并恢复数据', async ({ page }) => {
  await page.goto(APP_URL)
  
  // 监听 WS 消息
  const wsMessages: string[] = []
  page.on('websocket', ws => {
    ws.on('framereceived', frame => wsMessages.push(frame.payload.toString()))
  })
  
  // 等待收到行情数据
  await page.waitForTimeout(5000)
  const quoteMessages = wsMessages.filter(m => m.includes('market:quote'))
  expect(quoteMessages.length).toBeGreaterThan(0)
})
```

### 6. CI 集成

```yaml
# .github/workflows/e2e.yml
name: E2E Tests
on:
  schedule:
    - cron: '0 6 * * 1-5'  # 交易日早 6 点
  workflow_dispatch:

jobs:
  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: '1.25' }
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: cd frontend && npm ci
      - run: npx playwright install chromium
      - run: cd frontend && npx playwright test
        timeout-minutes: 10
```

## Acceptance Criteria

- [ ] `npx playwright test` 在本地可运行，启动 Wails dev + 执行测试 + 关闭
- [ ] 启动加载测试：确认欢迎面板、状态栏、命令栏可见
- [ ] 行情数据测试：搜索 600519 → 确认行情面板显示非零价格
- [ ] WS 测试：确认收到 `market:quote:*` 消息
- [ ] 交易测试：下单后订单面板出现对应条目
- [ ] 工作流测试：创建 → 执行 → 确认结果
- [ ] CI 中 E2E 可定时运行
- [ ] CHANGELOG 更新

## Risks / Trade-offs

| 风险 | 缓解 |
|------|------|
| Wails dev 启动慢（~10s） | 设置 `timeout: 30000`，在各 test 间复用进程 |
| 行情数据依赖外部 API | E2E 测试用 Playwright 网络拦截 mock 行情接口 |
| WebSocket 在 headless 模式下行为差异 | `WAILS_HEADLESS=1` 环境变量模拟无头模式 |
| CI 中无法启动图形界面 | Playwright 使用 `chromium` headless 模式；Wails dev 有 `-nocolor` 无头标志 |
| E2E 测试脆弱易断 | 只覆盖核心路径（启动、搜索、WS、工作流），不测试细粒度 UI 样式 |
