# 财务审计面板重设计

## Motivation

现有 AuditPanel 仅 72 行代码，功能极度简陋：
- 只展示 `GetAuditFindings` 返回的 5 个 finding 条目 + 纯文本风险等级
- 无评分明细、无财务指标、无历史趋势、无可视化
- Python 后端实际返回的丰富字段（`high_count`/`medium_count`）被忽略

## Design

### 数据流

前端同时并行调用两个后端方法，合并数据后渲染：

```
fetchData()
  ├── await app.GetAuditFindings(symbol)     ← detective_audit_risks
  │   └── findings[], risk_score, risk_grade, high_count, medium_count
  │
  └── await app.GetFinancialAnalysis(symbol)  ← analyze_report
      └── periods[12], health_score, health_grade,
          score_breakdown[], anomaly_flags[], metrics{}
```

### 修改文件

| 文件 | 改动 |
|------|------|
| `frontend/src/terminal/panels/AuditPanel.vue` | 完全重写：新增 gauge、KPI 卡片、评分明细、财务历史表 |
| `frontend/src/stores/data.ts` | 新增 `fetchFinancialAnalysis()` 方法（可选，或直接 panel 内调用） |

### API 变更

无。复用已有的 `GetAuditFindings` + `GetFinancialAnalysis`。

## Acceptance Criteria

- [ ] 风险等级 + 健康评分双 gauge 可视化（SVG 仪表盘或进度条）
- [ ] KPI 卡片行显示 5 个核心财务指标
- [ ] 评分明细可折叠展开
- [ ] 异常发现列表分类显示 (high/medium/low) 带详细说明
- [ ] 财务历史表格显示 12 期数据
- [ ] 面板加载时两个请求并行发出
- [ ] 走查无 TypeScript 错误

## Risks / Trade-offs

- 增加一次额外的 Go IPC 调用 (`GetFinancialAnalysis`)，但两个请求并行发出，总体耗时 ≈ max(审计, 分析) 而不是 sum
- `GetFinancialAnalysis` 内部也调用 `fetchFinancialJSON`，与 `GetAuditFindings` 重复获取财务数据。可以考虑后端缓存优化，但目前用户量小，直接调即可
