阶段 1: Engine-First — 里程碑拆分

Solo 开发 · 业余时间 · 按优先级串行推进 · 每个 M 有可验证产出

核心思想：引擎优先，UI 后置

Proposal 的阶段 1 是 4 线并行（Go 骨架 + 引擎 + Terminal UI + Workflow UI），Engine-First 改为 5 个串行里程碑，每个完成后都有可测试、可 demo 的产物。M5 完成时，工作流引擎已具备 CLI 运行能力——后续任何时间都可以加 Wails/Vue 壳。

里程碑一览

M1: Go 项目地基

基础骨架，无业务逻辑

  • Go module + 目录结构
  • Viper 配置 + slog 日志
  • SQLite WAL 连接 + 迁移框架
  • make test / make lint 就绪

验证: go build && go test ./... 全绿

M2: 节点系统

工作流引擎的原子单元

  • BaseNode 接口 + 端口/参数类型系统
  • NodeRegistry 注册发现
  • 首批 5 节点: DataLoader / SMA / CrossSignal / LogOutput / Loop
  • 节点验证 (端口类型匹配)

验证: 注册→创建→验证 单元测试通过

M3: DAG 执行引擎

阶段 1 的核心交付

  • DAG 拓扑排序 (Kahn)
  • goroutine 分层并行执行
  • channel 在节点间传递数据
  • 超时/取消/错误处理
  • LRU 节点结果缓存

验证: CLI 加载 workflow.json → 执行 → 输出结果

M4: 持久化与恢复

让工作流有记忆

  • SQLite 工作流存储 schema
  • JSON 序列化/反序列化完整图
  • 版本历史 (每次保存生成新版本)
  • 断点保存 → 从断点恢复执行

验证: 保存→修改→恢复→继续执行 全链路

M5: CLI 工具 + 测试覆盖

可交付的、可演示的开发工具

  • qf run workflow.json 执行工作流
  • qf nodes 列出所有注册节点
  • qf validate workflow.json 验证图合法性
  • 80%+ 单元测试覆盖
  • 性能基准测试 (100 节点 DAG)

验证: make test && make bench 全绿 + 覆盖率报告

与原 Proposal 的对比

维度 Proposal v1.0 Engine-First v2.0
前端 UI 6 周 (Terminal + Workflow Mode) 0 周 — 推迟到阶段 2
工作流引擎 4 周 (中间位置) 核心位置 — M2→M3→M4 三级递进
可演示产物 12 周后: 桌面应用 M3 即可 CLI demo, M5 完整交付
语言切换 Go ↔ Vue ↔ CSS 频繁切换 纯 Go, 零上下文切换
后续扩展 引擎+UI 耦合, 分离需重写 引擎独立包, 加 UI 无需改引擎

阶段 1 不在范围内的（留给后续阶段）

  • Wails v3 桌面壳 — M5 之后的可选扩展
  • DockView 停靠面板系统
  • vue-flow 工作流画布
  • Terminal Mode 任何面板
  • Python gRPC sidecar
  • 真实行情/券商连接

这些都是阶段 2+ 的内容。阶段 1 只做一件事：一个干净、可测试、CLI 可运行的工作流引擎。
